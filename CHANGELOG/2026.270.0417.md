# 2026.270.0417 — fix(deploy-vm)!: drop the retired vm:-prefixed teardown key (sdk#301 consumer leg)

## Summary

The **plugin-deploy-vm consumer leg of sdk#301** (`v0.2026270.3`). sdk#301 keys the per-host deploy state by the deploy **IDENTITY** (the VM entity lives in the entry's `vm:` cross-ref). This plugin's `OpPostTeardown` `RemoveEntries` list still named the retired `vm:<domain>` key, so a vm teardown left the identity-keyed entry behind — the entry-accumulation half of the same cutover.

- `vmPostTeardown` now ships the **domain identity** (plus the deploy name `p.Name`) as the entries to remove — both identity keys. No `vm:`-prefixed key remains in the list.
- The entry set is extracted to `vmTeardownRemoveEntries` and covered by a new test (fails pre-fix).
- sdk pin `v0.2026269.1752 → v0.2026270.152` (which carries #301 and the C6 `FindVmDeployNode` descent fix).
- **Dependency pins:** the `spec` pin moves `v0.2026269.1640 → v0.2026269.2150` — **required by the sdk pin**, whose own `go.mod` requires `spec v0.2026269.2150` (MVS resolves it; matching `go.sum`'s two new hashes).

This plugin's `PrepareVenue` deliberately ships **no** state patch (the authoritative writer is `candy/plugin-vm`, fixed in opencharly/plugin-vm#52), so no write-key change is needed here.
