# 2026.253.2106 — fix: re-pin sdk to v0.2026253.1947 — the deploy-hop from: resolves namespace-qualified templates (#248)

## Summary

The released plugin-deploy-vm v2026.253.1918 pins sdk v0.2026253.1714, whose `DeployTargetEntity` resolves a deploy's `from:` against the LOCAL vm map only. A clone-base bed whose `from:` is a git-linked namespace-qualified template (`omarchy.omarchy-vm`) fails the hop at prepare-venue with:

```
plugin-deploy-vm prepare-venue: resolve vm entity "check-omarchy-eval-edge-inst": resolve kind:vm entity "check-omarchy-eval-edge-inst": found but has no template body (a clone-base bed hop — resolve via the bed's own from:)
```

sdk #248 (v0.2026253.1947) adds the `ResolveKindEntityBody` fallback to the hop — the same surface vm-build's entity resolution uses. This PR adopts it:

- **candy/plugin-deploy-vm/go.mod**: sdk v0.2026253.1714 → v0.2026253.1947 (+ go.sum hashes)
- **candy/plugin-deploy-vm/lifecycle_hop_test.go**: +22 lines — the qualified-hop regression test (the exact `check-omarchy-eval-edge-inst` → `omarchy.omarchy-vm` shape)
