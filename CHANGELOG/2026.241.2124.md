# 2026.241.2124 — fix: bump sdk to v0.2026241.2117 for the machine-venue home-token fix

## Summary

Bumps `github.com/opencharly/sdk` from `v0.2026240.2049` to `v0.2026241.2117` (and `spec`
to `v0.2026241.1322`, pulled in by `go mod tidy`) to deliver the machine-venue
`{{.Home}}`-token fix to `target: vm` deploys.

This plugin walks deploy plans through `kit.WalkPlans`. Until sdk v0.2026241.2117 that walk
never resolved the deferred `{{.Home}}` token, so a candy's home-relative
`copy: to: ${HOME}/...` reached `PutFile` carrying the literal token and landed in a
directory named `{{.Home}}` inside the guest home — silently, no error, while `mkdir:`,
`write:` and `command:` from the same candy applied normally (those legs render shell that
expands `$HOME` on the venue).

The fix itself is opencharly/sdk#188; **this repin is what actually delivers it**, because
the plugin is built against its own pinned sdk rather than any checkout. Diff is `go.mod` +
`go.sum` only.

Refs opencharly/charly#460.

**End to end on a real VM — the changed path executing, before and after.**

A disposable Arch cloud-image VM bed applies a minimal candy whose plan is one `mkdir:`,
one `copy:` and one `write:` into the same directory, so the verbs are isolated from each
other.

*Before* (plugin built against the old sdk pin) — `copy:` silently does not deliver:

```
FAIL  check the copied file landed alongside the written one  [copyrepro-copy-landed]  exit=1
      copy: did NOT deliver. Directory contents:
      -rw-r--r-- written.txt        # write: applied, copied.txt absent

$ sudo find / -xdev -name copied.txt
/home/arch/{{.Home}}/copyprobe/copied.txt      # the literal token became a directory
```

*After* (the same bed, the plugin rebuilt against sdk v0.2026241.2117), full
`charly check run` R10 sequence including the fresh-rebuild leg:

```
3 steps: 3 passed, 0 failed, 0 skipped
PASS  check the copied file landed alongside the written one  [copyrepro-copy-landed]  exit=0
PASS  check dump what landed in the probe directory           [copyrepro-dump]         exit=0
PASS  check the candy dir marker is present at build scope    [copytest-present]        ok
EXIT=0
```

The "after" run was produced by pointing charly's fetched plugin checkout at the published
sdk tag — the same rebuild this repin causes — and the local cache was restored to the
published pin afterwards, so nothing outside this diff is carrying the change.
