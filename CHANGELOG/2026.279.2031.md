# 2026.279.2031 — fix(deploy-vm): adopt an sdk pin that strips the system config's retired `version:` stamp (plugin-deploy-vm#40)

## Summary

Adopt an sdk pin that strips the system config layer's retired `version:` stamp, so
`target: vm` deploys stop failing on every project on a host where the released charly
package wrote `/etc/charly/charly.yml`. Fixes #40.

### The defect

The released charly PACKAGE writes the system config layer `/etc/charly/charly.yml`
carrying a top-level `version:` stamp. spec #183 removed that key from the closed
`#NodeDoc`, so a leftover stamp resolves as a NODE named `version` whose value must be a
struct, and this plugin's resolve path
(`vmPrepareVenue` → `loaderkit.ResolveVmEntityViaExecutor` → `loaderkit.LoadUnified` →
`readConfigStack`) fails for **every** project on the host:

```
charly: error: command "deploy": … prepare venue: … resolve vm entity "cachyos-vm":
conflicting values "2026.261.1747" and {...} (mismatched types string and struct)
```

The system layer strips the retired key via `stripRetiredSystemDirectives`
(`loaderkit/config_stack.go`), but that fix entered the sdk at **`v0.2026276.1822`** while
this plugin pinned an earlier tag. Pasted (`grep -c`, the B14(d) evidence):

```
$ grep -c stripRetiredSystemDirectives $GOMODCACHE/github.com/opencharly/sdk@v0.2026273.207/loaderkit/config_stack.go
0
$ grep -c stripRetiredSystemDirectives $GOMODCACHE/github.com/opencharly/sdk@v0.2026279.1734/loaderkit/config_stack.go
3
```

### The fix

Bump `github.com/opencharly/sdk` → `v0.2026279.1734` (its transitive
`github.com/opencharly/spec` → `v0.2026276.0`, `go mod tidy`'d). R5 sweep — the old pin
string is gone from the module:

```
$ git grep -n 'v0.2026273.207' -- candy/plugin-deploy-vm/ ; echo "grep exit=$?"
grep exit=1     # 1 = no match = clean
$ grep -n 'opencharly/sdk' candy/plugin-deploy-vm/go.mod
5:require github.com/opencharly/sdk v0.2026279.1734
```

### R1 — the pre-existing errcheck findings in the same module

`golangci-lint` reported 6 `errcheck` findings in `iso_ssh_bootstrap.go` (the ISO-console
SSH bootstrap's `ConsoleRunner.TypeText`/`SendKeys` calls). They are pre-existing
(identical at the old sdk pin), but R1 forbids leaving a warning in place, so they are
fixed in a later commit: the keystrokes are best-effort **by construction** (a blind
console channel between discrete settle waits; the idempotent SSH probe at the top of
`EnsureIsoGuestSSH` is the real success signal), so the errors are explicitly discarded
with the sanctioned `_ =` form and a comment recording the mechanism. Behavior unchanged.
