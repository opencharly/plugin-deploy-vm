# 2026.269.1733 — chore: bump sdk to v0.2026269.1159 (the unconnected-kind from: exemption)

chore: bump sdk to v0.2026269.1159 (the unconnected-kind `from:` exemption)

Consumes the merged **opencharly/sdk#300**.

## Why

`prepare-venue` re-loads the project via `loaderkit.LoadUnifiedViaExecutor`, and
`ValidateCheckBeds` returns on the FIRST error. A project declaring a `kindcluster:`
bed (whose template is folded by `plugin-kube` — NOT compiled into this plugin) made
this re-load fail:

```
kind:check bed "check-kindcluster" references kindcluster entity
"check-kindcluster-cluster" which is not defined
```

so **every** `deploy:vm` prepare-venue failed, i.e. every VM deploy was un-runnable.

## Summary of changes (every diff item — A1)

`candy/plugin-deploy-vm/go.mod` / `go.sum`:

- **`github.com/opencharly/sdk` `v0.2026266.623 → v0.2026269.1159`** — the tag carrying
  sdk#300's `loaderkit.ValidateCheckBeds` exemption (`kindTemplatesAbsentHere`): a
  `from:` whose target structural kind folded ZERO templates in this scope is exempt.
  This is the fix.
- **`github.com/opencharly/spec` `v0.2026266.545 → v0.2026269.212`** — a **direct**
  dependency (the plugin imports `github.com/opencharly/spec/spec`), bumped because sdk
  `v0.2026269.1159`'s own `go.mod` declares `spec v0.2026269.212` as its floor; a
  consumer below that floor fails the contract-pin lockstep. It is NOT a transitive
  afterthought — it sits in a `require` block without the `// indirect` marker its
  neighbours carry precisely because it is imported directly.
- **`github.com/opencontainers/go-digest v1.0.0` and
  `github.com/opencontainers/image-spec v1.1.1`** — two new `// indirect` requires the
  newer sdk's dependency graph pulls in (`go mod tidy` materializes them). They are
  indirect and unused directly by this plugin's code.

No Go code changes: the sibling `loaderkit` fix IS the fix; this PR carries the pin so
the shipped plugin gets it.
