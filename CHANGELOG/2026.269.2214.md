# 2026.269.2214 — fix(deploy-vm): bump sdk to the host-renderer `install -d ''` fix (sdk#303)

## Summary

`plugin-deploy-vm` pinned `github.com/opencharly/sdk v0.2026269.1159`, which predates
`opencharly/sdk#303` (tag `v0.2026269.1353`). The sdk's machine-venue renderer
(`kit.RenderDownloadScript`) emitted `install -d -m0755 ''` for an `extract: sh`
download with **no `to:`** — exactly `layer-kubernetes`' helm step — and ignored
`unless_exists`. plugin-deploy-vm hands its executor straight to the shared
`kit.WalkPlans` (`plugin.go:90`), so every VM deploy walking that candy died with:

```
install: cannot create directory ''
charly: error: … plugin-deploy-vm: walk step "Op" (candy=kubernetes): exit status 1
```

observed live on the Phase 5 `check-kind-host-vm` bed (`add_candy: layer-kind` → its
`kubernetes` require). This is a stale-consumer-pin defect, not a bed defect: the sdk
fix existed, the VM plugin had not adopted it.

**Fix:** bump the sdk pin to `v0.2026269.1752` (the latest — it also carries the #687
ledger reverse-op fix; it lifts `spec` to `v0.2026269.1640`), and add
`host_render_test.go` at the plugin's **real entry point** (the `kit.WalkPlans` call
`plugin.go:90` makes) so a future pin regression fails CI.

## How tested

The new test **fails against the pre-fix pin and passes with the fix** — the R7
proof. Pre-fix (`go mod edit -require sdk@v0.2026269.1159 -require spec@v0.2026269.212`):

```
$ go test -run TestWalkPlans_HostDownloadGuardsAndEmptyTo .
--- FAIL: TestWalkPlans_HostDownloadGuardsAndEmptyTo (0.00s)
    host_render_test.go:75: empty-to download emitted install -d with an empty destination:
        …
        curl -fL --retry 3 -o "$ovtmp/archive" "…/get-helm-3"
        install -d -m0755 ''
        chmod +x "$ovtmp/archive"
        "$ovtmp/archive"
FAIL
```

Post-fix (the committed pin, `sdk v0.2026269.1752` / `spec v0.2026269.1640`):

```
$ gofmt -l .            # empty
$ go vet ./...          # clean
$ go test ./...
ok  	github.com/opencharly/plugin-deploy-vm/candy/plugin-deploy-vm
?   	github.com/opencharly/plugin-deploy-vm/candy/plugin-deploy-vm/cmd/serve	[no test files]
```

The test asserts, on the emitted machine-venue script: (a) no `install -d -m0755 ''`,
(b) `unless_exists` is honoured (`if [ -e '/usr/bin/helm' ]; then`), and (c) the script
parses under `sh -n`.
