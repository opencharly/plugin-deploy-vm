# 2026.246.1026 — feat(deploy-vm): bootstrap sshd + firewall + key on ISO guests via the console (mirrors omarchy bootstrap_ssh)

## Summary

Add full `bootstrap_ssh` support to charly for ISO-installed guests — mirroring exactly what the omarchy acceptance harness (`omarchy-iso-test` `bootstrap_ssh`) does, while keeping the existing authorized_keys approach and config intact.

**The problem (measured, not assumed):** an ISO-installed omarchy guest reaches the greeter with `systemctl is-active sshd` → **inactive** and the firewall port closed — the manual's "when authorized_keys is present, the install … enables sshd and opens the firewall" promise is not delivered by the 4.0.1 install path. The deploy then hangs at wait-for-sshd.

**The fix:**
- `EnsureIsoGuestSSH` (`iso_ssh_bootstrap.go`) runs for `source.kind: iso` BEFORE wait-for-sshd, through the console: switch to a text TTY, log in as the install user, then run exactly the harness's `bootstrap_ssh` commands — `authorized_keys` (grep-first, never duplicates), `ufw allow from 10.0.2.2 to any port 22 proto tcp`, `systemctl enable --now sshd`.
- `VirshConsoleRunner` types into the guest via libvirt send-key (valid Linux input-event key names — the chord map maps `ctrl`→`KEY_LEFTCTRL`, `alt`→`KEY_LEFTALT`, `ret`→`KEY_ENTER`, etc.).
- The SSH key is resolved through `spec/sshx.ResolveSSHPubKey` — the SAME resolver every other key-injection channel uses — one key across cloud-init / ISO-seed / libvirt-SMBIOS / console (R3).
- **Existing path intact:** idempotent — skips entirely when SSH already works (a distro whose installer DID honor authorized_keys). The cidata/authorized_keys generation is unchanged.

## How tested

**Unit tests** (`iso_ssh_bootstrap_test.go`) drive `EnsureIsoGuestSSH` with a fake `ConsoleRunner`/`RemoteRunner`:

```
$ go test ./...
ok  	github.com/opencharly/plugin-deploy-vm/candy/plugin-deploy-vm	0.012s
```

The sequence test asserts the exact `authorized_keys` / `ufw` / `systemctl` command lines + the console login chords (fails without the bootstrap); the skip test asserts no console calls when SSH already works. `go vet ./...` clean; `go build ./...` clean.

**Live verification** — on a fresh charly-cidata omarchy install, after running the exact `bootstrap_ssh` commands via the console:

```
$ timeout 20 charly vm ssh omarchy-vm "hostname; systemctl is-active sshd; echo SSH_WORKS"
omarchy
active
SSH_WORKS
```

The same bootstrap flow, wired into the deploy-vm lifecycle, is what `EnsureIsoGuestSSH` automates.
